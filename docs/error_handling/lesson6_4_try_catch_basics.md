### 🔑 例外処理の登場人物

```
┌─────────────────────────────────────────────────────────────┐
│                  例外処理の3つの登場人物                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  🎯 throw（スロー）= 投げる                                 │
│     「問題が起きた！」と報告する                            │
│     例：throw new Exception('エラーです');                  │
│                                                             │
│  🥅 catch（キャッチ）= 受け取る                             │
│     投げられた例外を受け取って処理する                      │
│     例：catch (Exception $e) { ... }                        │
│                                                             │
│  🏃 try（トライ）= 試す                                     │
│     「この中で例外が起きるかも」という範囲を指定            │
│     例：try { ... }                                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**👩‍💻ユーザー：** 「throw で投げて、catch で受け取る...」

**🐘ガネーシャ：** 「せや！野球のキャッチボールみたいなもんや」

```
    throw                         catch
      │                             │
      ▼                             ▼
  ┌───────┐      例外が飛ぶ！    ┌───────┐
  │ 投げる │ ─────────────────→ │ 受ける │
  │  側    │    （ボール）       │  側    │
  └───────┘                     └───────┘
```

## 🚀 第2章：try-catch の基本構文

### 🎭 一番シンプルな形

**🐘ガネーシャ：** 「まずは基本の書き方を見せたるわ」

```php
try {
    // 例外が起きるかもしれない処理
    $result = dangerousFunction();
    
} catch (Exception $e) {
    // 例外が起きた時の処理
    echo $e->getMessage();  // エラーメッセージを取得
}
```

**👩‍💻ユーザー：** 「try の中で問題が起きたら、catch に飛ぶんですか？」

**🐘ガネーシャ：** 「その通り！図で見てみよか」

```
┌─────────────────────────────────────────────────────────────┐
│                   try-catch の流れ                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  【正常時】                                                  │
│  try {                                                      │
│      処理1  ←─ 実行                                         │
│      処理2  ←─ 実行                                         │
│      処理3  ←─ 実行                                         │
│  } catch (...) {                                            │
│      ここは実行されない                                     │
│  }                                                          │
│                                                             │
│  ─────────────────────────────────────────                  │
│                                                             │
│  【例外発生時】                                              │
│  try {                                                      │
│      処理1  ←─ 実行                                         │
│      処理2  ←─ 💥 例外発生！                                │
│      処理3  ←─ 実行されない（スキップ）                     │
│  } catch (...) {                                            │
│      ここが実行される ←─ ジャンプ！                         │
│  }                                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

### 🔑 throw で例外を投げる

**🐘ガネーシャ：** 「例外は `throw` で投げるんや。詳しくは次回教えるけど、今は『こう書く』とだけ覚えといて」

```php
// 例外を投げる基本形
throw new Exception('エラーメッセージ');
```

**👩‍💻ユーザー：** 「throw すると、catch に飛ぶんですね」

**🐘ガネーシャ：** 「せや！throw の詳しい使い方は次回教えたるわ。今日は『try-catch で受け取る側』を理解することが大事や」

---

### 📝 Exception オブジェクトの中身

**🐘ガネーシャ：** 「catch で受け取った `$e` には、いろんな情報が入っとる」

```php
try {
    throw new Exception('何かがおかしい');
    
} catch (Exception $e) {
    // エラーメッセージ
    echo $e->getMessage();  // 「何かがおかしい」
    
    // エラーが起きたファイル
    echo $e->getFile();  // /app/Http/Controllers/TaskController.php
    
    // エラーが起きた行番号
    echo $e->getLine();  // 42
    
    // スタックトレース（どこから呼ばれたか）
    echo $e->getTraceAsString();
}
```

| メソッド | 説明 |
|----------|------|
| `getMessage()` | エラーメッセージ |
| `getFile()` | エラーが起きたファイル |
| `getLine()` | エラーが起きた行番号 |
| `getCode()` | エラーコード |
| `getTrace()` | スタックトレース（配列） |
| `getTraceAsString()` | スタックトレース（文字列） |

## 🎯 第3章：Controller で try-catch を使ってみる

### 🎭 シナリオ：タスク完了処理

**🐘ガネーシャ：** 「実際のコードで try-catch を使ってみよか」

#### Before：try-catch なし

```php
public function complete(Request $request, Task $task)
{
    // 状態チェック
    if ($task->status !== 'doing') {
        return response()->json([
            'message' => '作業中のタスクのみ完了できます',
        ], 409);
    }

    $task->update(['status' => 'done']);
    
    return new TaskResource($task);
}
```

**👩‍💻ユーザー：** 「これは前回学んだ書き方ですね」

**🐘ガネーシャ：** 「せや。でも、もし `update()` の中でエラーが起きたらどうなる？」

**👩‍💻ユーザー：** 「えっと...500エラーになりますか？」

**🐘ガネーシャ：** 「そう！ユーザーには『Server Error』としか表示されへん」

---

#### After：try-catch あり

```php
public function complete(Request $request, Task $task)
{
    // 状態チェック
    if ($task->status !== 'doing') {
        return response()->json([
            'message' => '作業中のタスクのみ完了できます',
        ], 409);
    }

    try {
        $task->update(['status' => 'done']);
        $task->load('createdBy');
        
        return new TaskResource($task);
        
    } catch (Exception $e) {
        // エラーをログに記録
        Log::error('タスク完了エラー: ' . $e->getMessage());
        
        // ユーザーにはカスタムメッセージを返す
        return response()->json([
            'message' => 'タスクの完了処理中にエラーが発生しました',
        ], 500);
    }
}
```

**👩‍💻ユーザー：** 「catch の中で、ログを記録してカスタムメッセージを返してるんですね！」

**🐘ガネーシャ：** 「せや！これで『何が起きたか』を把握しつつ、ユーザーには分かりやすいメッセージを返せる」

### 📊 try-catch を書く？書かない？

| 状況 | try-catch | 理由 |
|------|-----------|------|
| 通常のDB操作 | 書かなくてもOK | Laravel が自動処理 |
| エラーメッセージをカスタマイズしたい | 書く | 自分で制御したい |
| エラーをログに記録したい | 書く | 記録が必要 |
| 失敗しても処理を続けたい | 書く | 握りつぶしではなく意図的に |
| 外部API連携 | 書く | 失敗時の対応が必要 |

**🐘ガネーシャ：** 「基本的には Laravel に任せて、『自分で制御したい時だけ』try-catch を書くんや」

### 🎯 Laravel が自動で処理する例外

**🐘ガネーシャ：** 「Laravel は、よくある例外を自動でいい感じに処理してくれる」

```php
// ModelNotFoundException → 404 Not Found
$task = Task::findOrFail($id);  // 見つからない → 自動で 404

// ValidationException → 422 Unprocessable Entity
$request->validate([...]);  // バリデーション失敗 → 自動で 422

// AuthenticationException → 401 Unauthorized
// 認証失敗 → 自動で 401
```

| 例外クラス | HTTPステータス | 発生する場面 |
|------------|---------------|--------------|
| `ModelNotFoundException` | 404 | `findOrFail()` で見つからない |
| `ValidationException` | 422 | バリデーション失敗 |
| `AuthenticationException` | 401 | 認証失敗 |
| `AuthorizationException` | 403 | 認可失敗 |
| `その他の Exception` | 500 | 予期しないエラー |

**👩‍💻ユーザー：** 「だから Route Model Binding や FormRequest を使うと、自動でエラーが返るんですね！」

**🐘ガネーシャ：** 「せや！Lesson6-2 で学んだ『Laravel が自動でやってくれること』は、この仕組みのおかげなんや」

## 📝 第5章：Exception の種類

### 🎭 色んな Exception がある

**🐘ガネーシャ：** 「Exception にも色んな種類があるんや」

```php
// 基本の Exception
throw new Exception('一般的なエラー');

// PHP 組み込みの例外
throw new InvalidArgumentException('引数が不正です');
throw new RuntimeException('実行時エラーです');
throw new LogicException('ロジックエラーです');

// Laravel の例外
throw new ModelNotFoundException('モデルが見つかりません');
throw new ValidationException::withMessages(['field' => ['エラー']]);

// Symfony の HTTP 例外（Laravel でも使える）
throw new HttpException(404, 'Not Found');
throw new HttpException(403, 'Forbidden');
throw new HttpException(409, 'Conflict');
```

| 例外クラス | 用途 | HTTPステータス |

| `Exception` | 一般的なエラー | 500 |
| `InvalidArgumentException` | 引数が不正 | 500 |
| `RuntimeException` | 実行時エラー | 500 |
| `ModelNotFoundException` | モデルが見つからない | 404 |
| `ValidationException` | バリデーションエラー | 422 |

```php
namespace App\Exceptions;

class TaskNotCompletableException extends Exception
```

## 🎯 第6章：実践 - Controller での try-catch

### 🎭 実際のコードで使ってみよう

**🐘ガネーシャ：** 「タスク完了の処理で、try-catch を使ってみよか」

```php
// TaskController.php

public function complete(Request $request, Task $task)
{
    // 権限チェック
    $isMember = $task->project->users()
        ->where('users.id', $request->user()->id)
        ->exists();

    if (!$isMember) {
        return response()->json([
            'message' => 'このプロジェクトにアクセスする権限がありません',
        ], 403);
    }

    // 状態チェック
    if ($task->status !== 'doing') {
        return response()->json([
            'message' => '作業中のタスクのみ完了できます',
        ], 409);
    }

    try {
        // DB操作
        $task->update(['status' => 'done']);
        $task->load('createdBy');

        return new TaskResource($task);

    } catch (Exception $e) {
        // エラーログを記録
        Log::error('タスク完了処理でエラー', [
            'task_id' => $task->id,
            'user_id' => $request->user()->id,
            'error' => $e->getMessage(),
        ]);

        return response()->json([
            'message' => 'タスクの完了処理中にエラーが発生しました',
        ], 500);
    }
}
```

```

│                                                             │
│  1️⃣ 権限チェック・状態チェックは try の外                   │

│                                                             │
│  2️⃣ DB操作は try の中                                       │
```

## 📝 演習課題

### Q1：以下のコードの実行結果を答えてください

```php
try {
    echo "A";
    throw new Exception("エラー発生");
    echo "B";
} catch (Exception $e) {
    echo "C";
}
echo "D";
```

<details>
<summary>📖 答えを見る</summary>

**出力：** `ACD`

**解説：**
1. `A` が出力される
2. 例外が throw される
3. `B` はスキップされる（例外発生後は実行されない）
4. catch に飛んで `C` が出力される
5. try-catch の後の `D` が出力される

</details>

<summary>📖 答えを見る</summary>

```php
public function store(Request $request, Project $project)
{
    try {
        $task = Task::create([
            'project_id' => $project->id,
            'title' => $request->title,
            'status' => 'todo',
            'created_by' => $request->user()->id,
        ]);

        return new TaskResource($task);

    } catch (Exception $e) {
        Log::error('タスク作成エラー', [
            'project_id' => $project->id,
            'user_id' => $request->user()->id,
            'error' => $e->getMessage(),
        ]);

        return response()->json([
            'message' => 'タスクの作成中にエラーが発生しました',
        ], 500);
    }
}
```

### Q3：以下の場合、try-catch を書くべきですか？書かなくてもいいですか？

```
1. findOrFail() でタスクを取得する
2. 外部のAPIにリクエストを送る
3. FormRequest でバリデーションする
4. ファイルをアップロードする
```

<details>
<summary>📖 答えを見る</summary>

| 場合 | 回答 | 理由 |
|------|------|------|
| 1. findOrFail() | 書かなくてもOK | Laravel が自動で 404 を返す |
| 2. 外部API | **書くべき** | 失敗時の対応が必要、タイムアウトなど |
| 3. FormRequest | 書かなくてもOK | Laravel が自動で 422 を返す |
| 4. ファイルアップロード | **書くべき** | ディスク容量不足など予期しないエラーがありうる |

</details>
