## 📖 第 1 章：トランザクションとは何か

### 🎭 例え話：銀行振込

**🐘 ガネーシャ：** 「トランザクションを理解するには、銀行振込を考えるとええで」

```
┌─────────────────────────────────────────────────────────────┐
│                    銀行振込の流れ                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  【Aさん → Bさんに 10,000円 振込】                          │
│                                                             │
│  ステップ1: Aさんの口座から 10,000円 引く                   │
│  ステップ2: Bさんの口座に 10,000円 足す                     │
│                                                             │
│  💥 もしステップ1の後、ステップ2の前にエラーが起きたら？   │
│                                                             │
│  Aさん: -10,000円 😱                                        │
│  Bさん: +0円                                                │

│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**👩‍💻 ユーザー：** 「1 万円が消えちゃう...それは大問題ですね」

**🐘 ガネーシャ：** 「せや。だからこの 2 つの操作は『セット』で考えなアカンのや」

### 🔑 トランザクションの基本概念

**🐘 ガネーシャ：** 「トランザクションは『全部成功するか、全部なかったことにするか』を保証する仕組みや」

```
┌─────────────────────────────────────────────────────────────┐
│                 トランザクションとは                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  複数の処理を「1つの塊」として扱う仕組み                    │
│                                                             │
│  【ルール】                                                  │
│  ├── 全部成功 → 全部確定（コミット）                       │
│  └── 1つでも失敗 → 全部取り消し（ロールバック）            │
│                                                             │
│  【銀行振込の場合】                                          │
│  ├── 両方成功 → お金が移動する ✅                          │
│  └── どちらか失敗 → 何も起きなかったことにする ✅          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**👩‍💻 ユーザー：** 「『全部成功』か『全部失敗』か、どちらかしかないんですね」

**🐘 ガネーシャ：** 「せや！中途半端な状態にならんから、データの整合性が保たれるんや」

---

### 📊 用語を覚えよう

| 用語                         | 意味                   | 銀行で言うと   |
| ---------------------------- | ---------------------- | -------------- |
| **トランザクション**         | 複数の処理をまとめた塊 | 振込処理全体   |
| **コミット（Commit）**       | 処理を確定する         | 振込完了       |
| **ロールバック（Rollback）** | 処理を取り消す         | 振込キャンセル |

**🐘 ガネーシャ：** 「ワシの教え子のロスチャイルドくんが銀行作った時も、最初はこれで苦労しとったわ」

**👩‍💻 ユーザー：** 「ロスチャイルド...？いつの時代の話ですか...」

**🐘 ガネーシャ：** 「細かいことはええねん！」

## 🚀 第 3 章：Laravel でのトランザクションの書き方

### 🎭 方法 1：DB::transaction()（おすすめ）

**🐘 ガネーシャ：** 「Laravel で一番シンプルな書き方がこれや」

```php
use Illuminate\Support\Facades\DB;

public function execute(array $data, User $user): Project
{
    return DB::transaction(function () use ($data, $user) {
        // この中の処理は全部「1つの塊」として扱われる

        $project = Project::create([
            'name' => $data['name'],
            'is_archived' => $data['is_archived'] ?? false,
        ]);

        $project->users()->attach($user->id, [
            'role' => 'project_owner',
        ]);

        $project->load(['users']);

        return $project;
    });
}
```

**👩‍💻 ユーザー：** 「`DB::transaction()` で囲むだけでいいんですか？」

**🐘 ガネーシャ：** 「せや！この中で例外が起きたら、自動でロールバックしてくれる」

---

### 📊 DB::transaction() の動き

```
┌─────────────────────────────────────────────────────────────┐
│              DB::transaction() の動き                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  【正常時】                                                  │
│  DB::transaction(function () {                              │
│      処理1  ←─ 実行（仮保存）                               │
│      処理2  ←─ 実行（仮保存）                               │
│      処理3  ←─ 実行（仮保存）                               │
│  });                                                        │
│  ↓                                                          │
│  自動でコミット ✅ → 全部確定！                             │
│                                                             │
│  ─────────────────────────────────────────                  │
│                                                             │
│  【例外発生時】                                              │
│  DB::transaction(function () {                              │
│      処理1  ←─ 実行（仮保存）                               │
│      処理2  ←─ 💥 例外発生！                                │
│      処理3  ←─ 実行されない                                 │
│  });                                                        │
│  ↓                                                          │
│  自動でロールバック 🔙 → 処理1も取り消し！                  │
│  ↓                                                          │
│  例外が再スロー → Laravel のエラーハンドリングへ            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**👩‍💻 ユーザー：** 「try-catch を書かなくても、自動でロールバックしてくれるんですね！」

**🐘 ガネーシャ：** 「せや！Lesson 6-5 で『Laravel に任せる』って教えたやろ？これも同じ考え方や」

### 🔑 ポイント：クロージャと use

**👩‍💻 ユーザー：** 「`function () use ($data, $user)` の `use` って何ですか？」

**🐘 ガネーシャ：** 「ええ質問や。クロージャ（無名関数）の中で外の変数を使うための書き方や」

```php
// use がないと、$data や $user が使えない
DB::transaction(function () use ($data, $user) {
    // ↑ use で渡した変数だけ使える
    $project = Project::create([
        'name' => $data['name'],  // $data が使える
    ]);

    $project->users()->attach($user->id, [...]); // $user が使える
});
```

**👩‍💻 ユーザー：** 「なるほど、外の変数を中に持ち込むためのキーワードなんですね」

---

### 🎯 方法 2：手動で書く場合

**🐘 ガネーシャ：** 「もう一つの書き方も教えとくわ。こっちは細かい制御が必要な時に使う」

```php
use Illuminate\Support\Facades\DB;

public function execute(array $data, User $user): Project
{
    DB::beginTransaction();

    try {
        $project = Project::create([
            'name' => $data['name'],
            'is_archived' => $data['is_archived'] ?? false,
        ]);

        $project->users()->attach($user->id, [
            'role' => 'project_owner',
        ]);

        $project->load(['users']);

        DB::commit();  // 成功したら確定

        return $project;

    } catch (Exception $e) {
        DB::rollBack();  // 失敗したら取り消し
        throw $e;        // 例外を再スロー
    }
}
```

---

### 📊 2 つの書き方の比較

| 項目         | DB::transaction() | beginTransaction / commit |
| ------------ | ----------------- | ------------------------- |
| コード量     | 少ない ✅         | 多い                      |
| try-catch    | 不要 ✅           | 必要                      |
| ロールバック | 自動 ✅           | 手動                      |
| 細かい制御   | できない          | できる ✅                 |
| おすすめ度   | ⭐⭐⭐            | ⭐⭐                      |

**🐘 ガネーシャ：** 「普通は `DB::transaction()` を使えばええ。手動で書くのは、途中で条件分岐して commit したい時とかや」

**👩‍💻 ユーザー：** 「シンプルな方を使います！」

## ⚠️ 第 6 章：トランザクションの注意点

### 🎭 注意点 1：外部 API 呼び出しは含めない

**🐘 ガネーシャ：** 「トランザクションの中に外部 API 呼び出しを入れたらアカンで」

```php
// ❌ ダメな例
DB::transaction(function () use ($task, $user) {
    $task->update(['status' => 'done']);

    // 外部APIは失敗してもロールバックできない！
    $this->slackNotifier->notify("タスク完了");

    TaskHistory::create([...]);
});
```

**👩‍💻 ユーザー：** 「なんでダメなんですか？」

**🐘 ガネーシャ：** 「Slack 通知は送ったらロールバックできへんやろ？DB はロールバックできても、送った通知は取り消せへん」

```
┌─────────────────────────────────────────────────────────────┐
│              外部API呼び出しの問題                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  DB::transaction(function () {                              │
│      Task更新      ←─ ロールバック可能 ✅                   │
│      Slack通知     ←─ ロールバック不可能 ❌（送ったら終わり）│
│      履歴記録      ←─ 💥 ここで失敗！                       │
│  });                                                        │
│                                                             │
│  結果：                                                     │
│  ・Task更新 → ロールバックされた                            │
│  ・Slack通知 → 送信済み（取り消せない）                     │
│  ・履歴 → 記録されてない                                    │
│                                                             │
│  → Slackには「完了」と通知されたのに、実際は完了してない！  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

### ✅ 正しい書き方：外部 API はトランザクションの外

```php
public function execute(Task $task, User $user): Task
{
    // トランザクション内はDBのみ
    $task = DB::transaction(function () use ($task, $user) {
        $task->update(['status' => 'done']);

        TaskHistory::create([
            'task_id' => $task->id,
            'action' => 'completed',
            'user_id' => $user->id,
        ]);

        return $task;
    });

    // 外部APIはトランザクションの外
    try {
        $this->slackNotifier->notify("タスク「{$task->title}」が完了しました");
    } catch (Exception $e) {
        // 通知失敗してもタスク完了自体は成功させる
        Log::warning('Slack通知失敗: ' . $e->getMessage());
    }

    return $task;
}
```

**👩‍💻 ユーザー：** 「DB の処理と外部 API の処理を分けるんですね」

**🐘 ガネーシャ：** 「せや！Lesson 6-5 で教えた『失敗しても処理を続けたい場合』がここで活きてくるんや」

## 📝 演習課題

### Q1：以下のコードにトランザクションが必要か判断してください

```php
// ケース1：タスクのステータス更新
public function execute(Task $task): Task
{
    $task->update(['status' => 'doing']);
    return $task;
}

// ケース2：メンバー追加
public function execute(Project $project, User $user): void
{
    $project->users()->attach($user->id, [
        'role' => 'project_member',
    ]);

    ActivityLog::create([
        'project_id' => $project->id,
        'action' => 'member_added',
        'user_id' => $user->id,
    ]);
}
```

<details>
<summary>📖 答えを見る</summary>

**ケース 1：不要**

-   1 つのテーブルの 1 レコードを更新するだけ
-   他に影響を与える処理がない

**ケース 2：必要 ✅**

-   2 つのテーブルを更新している（memberships, activity_logs）
-   メンバー追加とログ記録はセットで成功すべき

```php
// 修正版
public function execute(Project $project, User $user): void
{
    DB::transaction(function () use ($project, $user) {
        $project->users()->attach($user->id, [
            'role' => 'project_member',
        ]);

        ActivityLog::create([
            'project_id' => $project->id,
            'action' => 'member_added',
            'user_id' => $user->id,
        ]);
    });
}
```

</details>

### Q2：以下のコードの問題点を指摘してください

```php
public function execute(Task $task, User $user): Task
{
    return DB::transaction(function () use ($task, $user) {
        $task->update(['status' => 'done']);

        // Slack通知
        Http::post('https://slack.com/api/chat.postMessage', [
            'channel' => '#tasks',
            'text' => "タスク完了: {$task->title}",
        ]);

        TaskHistory::create([
            'task_id' => $task->id,
            'action' => 'completed',
        ]);

        return $task;
    });
}
```

<details>
<summary>📖 答えを見る</summary>

**問題点：外部 API（Slack 通知）がトランザクション内にある**

-   Slack 通知は送信したらロールバックできない
-   TaskHistory の create が失敗すると、DB はロールバックされるが Slack は送信済み
-   「完了通知が来たのに、実際は完了してない」という矛盾が発生

**修正版：**

```php
public function execute(Task $task, User $user): Task
{
    $task = DB::transaction(function () use ($task, $user) {
        $task->update(['status' => 'done']);

        TaskHistory::create([
            'task_id' => $task->id,
            'action' => 'completed',
        ]);

        return $task;
    });

    // 外部APIはトランザクションの外
    try {
        Http::post('https://slack.com/api/chat.postMessage', [
            'channel' => '#tasks',
            'text' => "タスク完了: {$task->title}",
        ]);
    } catch (Exception $e) {
        Log::warning('Slack通知失敗: ' . $e->getMessage());
    }

    return $task;
}
```

</details>
