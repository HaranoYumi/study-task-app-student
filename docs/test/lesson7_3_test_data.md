```php
<?php
// tests/Feature/Api/UserTest.php（まだ問題がある例）

namespace Tests\Feature\Api;

use App\Models\User;
use Tests\TestCase;

class UserTest extends TestCase
{
    public function test_認証済みユーザーの情報を取得できる(): void
    {
        // ============================================
        // 1. Arrange（準備）
        // ============================================
        // ユーザーを直接作成してみる
        $user = new User();
        $user->name = 'テスト太郎';
        $user->email = 'test@example.com';
        $user->password = bcrypt('password');
        $user->save();

        // ============================================
        // 2. Act（実行）
        // ============================================
        // このユーザーとしてログインした状態でリクエスト
        $response = $this->actingAs($user)
            ->getJson('/api/user');

        // ============================================
        // 3. Assert（検証）
        // ============================================
        $response->assertStatus(200);
        $response->assertJson([
            'name' => 'テスト太郎',
            'email' => 'test@example.com',

    }
}
```

## 📖 第2章：RefreshDatabase を理解しよう

### 🎭 RefreshDatabase って何？

**🐘ガネーシャ：** 「まず RefreshDatabase から説明するで。これは**テストのたびにDBをリセットしてくれる魔法**や」

**👩‍💻ユーザー：** 「魔法...！」

---

### 📝 使い方

**🐘ガネーシャ：** 「使い方は超簡単。テストクラスに1行追加するだけや」

```php
<?php

namespace Tests\Feature\Api;

use Illuminate\Foundation\Testing\RefreshDatabase;  // ← これを追加
use Tests\TestCase;

class UserTest extends TestCase
{
    use RefreshDatabase;  // ← これを追加するだけ！

    public function test_認証済みユーザーの情報を取得できる(): void
    {
        // ...
    }
}
```

**👩‍💻ユーザー：** 「`use RefreshDatabase;` を書くだけ？」

**🐘ガネーシャ：** 「せや！これだけで、**テストメソッドが実行されるたびにDBがリセット**されるんや」

---

### 🔍 RefreshDatabase の仕組み

**🐘ガネーシャ：** 「裏で何が起きてるか説明するで」

```
┌─────────────────────────────────────────────────────────────┐
│              RefreshDatabase の仕組み                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  【テスト1回目】                                            │
│                                                             │
│  1. テスト開始前                                            │
│     → DBをマイグレーション（テーブル作成）                 │
│     → DBは空っぽの状態 ✨                                  │
│                                                             │
│  2. テスト実行                                              │
│     → ユーザーを作成                                       │
│     → テスト実行                                           │
│     → ユーザーがDBに存在                                   │
│                                                             │
│  3. テスト終了後                                            │
│     → トランザクションをロールバック                       │
│     → DBが空っぽに戻る ✨                                  │
│                                                             │
│  【テスト2回目】                                            │
│                                                             │
│  1. テスト開始前                                            │
│     → DBは空っぽの状態 ✨（リセット済み）                  │
│                                                             │
│  2. テスト実行                                              │
│     → また新しいユーザーを作成できる！                     │
│     → 重複エラーにならない！                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**👩‍💻ユーザー：** 「なるほど！毎回リセットされるから、何回テストしても大丈夫なんですね！」

**🐘ガネーシャ：** 「せや！しかも**本番のDBには影響しない**。テスト用のDBだけがリセットされるんや」

---

### 📝 Factory ファイルの中身を見てみよう

**🐘ガネーシャ：** 「実際の Factory ファイルの中身を見てみよか」

```php
<?php
// database/factories/UserFactory.php

namespace Database\Factories;

use Illuminate\Database\Eloquent\Factories\Factory;
use Illuminate\Support\Facades\Hash;
use Illuminate\Support\Str;

class UserFactory extends Factory
{
    protected static ?string $password;  // パスワードを保持

    /**
     * モデルのデフォルト状態を定義
     */
    public function definition(): array
    {
        return [
            'name' => $this->faker?->name() ?? 'User',
            'email' => $this->faker?->unique()->safeEmail() ?? Str::random(10) . '@example.com',
            'email_verified_at' => now(),
            'password' => static::$password ??= Hash::make('password'),
            'remember_token' => Str::random(10),
        ];
    }
}
```

**👩‍💻ユーザー：** 「おお！`definition()` メソッドでデフォルト値を定義してるんですね」

**🐘ガネーシャ：** 「せや！このファイルが『工場の設計図』みたいなもんや」

### 🔍 Factory ファイルの解説

```
┌─────────────────────────────────────────────────────────────┐
│              Factory ファイルの解説                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  $this->faker?->name() ?? 'User'                            │
│  └─ ランダムな名前を生成（例: "John Doe", "山田 太郎"）    │
│     faker が使えない場合は 'User' をデフォルト値として使用 │
│                                                             │
│  $this->faker?->unique()->safeEmail() ?? Str::random(10)... │
│  └─ ユニークなランダムメールアドレスを生成                 │
│     （例: "john.doe@example.com"）                          │
│     faker が使えない場合はランダム文字列のメールを生成     │
│                                                             │
│  now()                                                      │
│  └─ 現在日時（email_verified_at に設定 = 認証済み）        │
│                                                             │
│  static::$password ??= Hash::make('password')               │
│  └─ 'password' を暗号化（全ユーザー共通のパスワード）      │
│     static プロパティで1度だけ生成し再利用（効率化）       │
│                                                             │
│  ─────────────────────────────────────────────────          │
│                                                             │
│  💡 $this->faker は Laravel の Faker ライブラリ             │
│     → テスト用のダミーデータを自動生成してくれる           │
│     → ?-> でnullセーフにアクセス（faker が null でもOK）   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**👩‍💻ユーザー：** 「`$this->faker` がランダムなデータを作ってくれるんですね！」

**🐘ガネーシャ：** 「せや！毎回違う名前やメールアドレスが生成されるから、重複の心配がないんや」

### 🎭 Factory + RefreshDatabase を使ったテスト

**🐘ガネーシャ：** 「ほな、さっきの失敗したテストを正しく書き直してみよか」

```php
<?php
// tests/Feature/Api/UserTest.php（正しい例）

namespace Tests\Feature\Api;

use App\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class UserTest extends TestCase
{
    use RefreshDatabase;  // ← これでDBが毎回リセット！

    /**
     * 認証済みユーザーの情報を取得できる
     */
    public function test_認証済みユーザーの情報を取得できる(): void
    {
        // ============================================
        // 1. Arrange（準備）
        // ============================================
        // Factory でユーザーを作成（1行！）
        $user = User::factory()->create([
            'name' => '山田太郎',
            'email' => 'yamada@example.com',
        ]);

        // ============================================
        // 2. Act（実行）
        // ============================================
        // actingAs でログイン状態にしてリクエスト
        $response = $this->actingAs($user)
            ->getJson('/api/user');

        // ============================================
        // 3. Assert（検証）
        // ============================================
        $response->assertStatus(200);
        $response->assertJson([
            'name' => '山田太郎',
            'email' => 'yamada@example.com',
        ]);
    }
}
```

**👩‍💻ユーザー：** 「おお、スッキリ！」

```
│      → Lesson 7-2 の TestController は DB 不要だった       │
│      → 実際の API（/api/user など）は DB が必要            │
│                                                             │
│  2️⃣  RefreshDatabase でDBをリセット                         │
│      use RefreshDatabase; を書くだけ！                      │
│      → テストごとにDBがクリーンになる                      │
│      → 何回実行しても重複エラーにならない                  │
│                                                             │
│  3️⃣  Factory でテストデータを簡単作成                       │
│      User::factory()->create([...]);                        │
│      → 1行でユーザーが作れる                               │
│      → 必要な値だけ指定、残りはおまかせ                    │
│                                                             │
│  4️⃣  Factory ファイルの場所と作り方                         │
│      → database/factories/ フォルダにある                  │
│      → sail artisan make:factory で新規作成               │
│      → definition() でデフォルト値を定義                   │
│                                                             │
│  5️⃣  actingAs() でログイン状態を作る                        │
│      $this->actingAs($user)->getJson(...);                  │
│      → Postman で4ステップ必要だった作業が1行             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
